# Путь к реальной торговле

Пошаговый гайд от «код склонирован» до «торгует реальными деньгами». Для
инцидентов после запуска — [RUNBOOK.md](RUNBOOK.md), не сюда. Для
архитектуры/полного списка возможностей — [README.md](README.md), этот
файл — только последовательность действий и что куда вписывать.

**Главное правило всего гайда: каждый следующий этап начинается только
после того, как предыдущий прошёл БЕЗ вопросов.** Пропуск этапа ради
скорости — это не сокращение пути, это перенос риска с рынка на
необнаруженный баг в коде.

---

## Обзор этапов

| # | Этап | Риск денег | Типичное время |
|---|---|---|---|
| 0 | Установка | нет | 15 минут |
| 1 | Конфигурация | нет | 1-3 часа (первый раз) |
| 2 | DRY_RUN против живых данных | нет | несколько дней на стратегию |
| 3 | Форк-тест (anvil) | нет (форк — не настоящая сеть) | 1-2 дня |
| 4 | Пилот на малом реальном капитале | да, но маленький ($50-200) | 2-4 недели |
| 5 | Масштабирование и постоянная работа | да | бессрочно |

## Этап 0: Установка

```bash
git clone <ваш форк или оригинал>
cd Wakefinder
pip install -e ".[dev,web]"
cp .env.example .env
```

`.env` — единственный файл, который вы будете реально редактировать
дальше. Он уже в `.gitignore` — секреты туда не попадут в git по
умолчанию, но всё равно не публикуйте его нигде.

## Этап 1: Конфигурация — что вписывать и зачем

### 1.1 RPC-эндпоинты

```
ETH_RPC_WS_URL=wss://...
ETH_RPC_HTTP_URL=https://...
```

Оба обязательны для любой ETH-стратегии, и оба — платные (Alchemy,
Infura, QuickNode) начиная с нужного вам уровня скорости — бесплатные
тарифы обычно режут лимит запросов и/или скорость мемпул-подписки, а это
и есть то, за что бот в принципе конкурирует. WS и HTTP — РАЗНЫЕ URL у
большинства провайдеров (не один и тот же адрес с другой схемой), не
пытайтесь один вывести из другого.

Для Solana-стратегий:
```
SOLANA_RPC_HTTP_URL=https://...
```

### 1.2 Кошельки — САМОЕ ВАЖНОЕ, где чаще всего ошибаются

```
ETH_PRIVATE_KEY=0x...
FLASHBOTS_SIGNER_KEY=0x...
```

Это ДВА РАЗНЫХ ключа, и они обязаны отличаться (проверка при старте
упадёт, если они совпадают). `ETH_PRIVATE_KEY` — кошелёк, который реально
держит капитал и подписывает торговые транзакции. `FLASHBOTS_SIGNER_KEY`
— отдельная идентичность для репутации у Flashbots-релея, деньги на нём
не нужны, использовать можно даже пустой свежесгенерированный кошелёк.

**Для каждой стратегии — свой `ETH_PRIVATE_KEY`.** Не переиспользуйте
один и тот же кошелёк между профилями, которые будете запускать
одновременно — параллельная отправка транзакций с одного адреса ломает
подсчёт nonce. Каждый новый кошелёк — это НОВЫЙ адрес специально под этот
процесс, не тот, которым вы пользуетесь для чего-то ещё.

Альтернатива голому ключу в `.env` — зашифрованный файл:
```bash
python -m wakefinder.common.keystore /path/to/eth.enc
```
Спросит ключ и пассфразу интерактивно. Тогда в `.env`:
```
ETH_PRIVATE_KEY_FILE=/path/to/eth.enc
WALLET_KEY_PASSPHRASE=...
```
(`WALLET_KEY_PASSPHRASE` обязателен, если используете хоть один
`*_KEY_FILE`; либо голый ключ, либо файл — ровно один источник, не оба
сразу.) Для Solana — так же, `SOLANA_PRIVATE_KEY`/`SOLANA_PRIVATE_KEY_FILE`,
если планируете Solana-стратегии.

### 1.3 Адреса контрактов — что уже верно, что СЛОМАНО

В `common/config.py` есть дефолты для роутеров/Aave/Uniswap V3 —
**не все они одинаково надёжны**:

- `ETH_ROUTER_ADDRESS`, `AAVE_POOL_ADDRESS`, `JIT_NPM_ADDRESS`,
  `JIT_SWAP_ROUTER_ADDRESS` — синтаксически валидные адреса, есть в
  собственном allowlist проекта. Всё равно не проверены вживую (нет
  сетевого доступа в среде, где писался код) — сверьте с официальными
  источниками (Uniswap docs, aave-address-book) перед реальными деньгами,
  но как минимум формат правильный.
- `AAVE_POOL_DATA_PROVIDER_ADDRESS` и `AAVE_PRICE_ORACLE_ADDRESS` —
  **известно битые** (39 hex-символов вместо 40, не проходят даже
  базовую проверку формата). Бот запустится (это специально не блокирует
  остальные стратегии), но громко предупредит в лог при старте. Если
  планируете `liquidate` или `jit` — ОБЯЗАТЕЛЬНО замените оба на реальные
  адреса из https://github.com/bgd-labs/aave-address-book до запуска
  этих двух стратегий, иначе они упадут при первом обращении к контракту.

### 1.4 Выбор стратегии — TOML-профиль

11 готовых примеров в `configs/`:
```
eth-arb.toml                    eth-copytrade-conservative.toml
eth-copytrade-fast-memecoin.toml eth-snipe.toml
eth-snipe-backrun.toml          eth-liquidate.toml
eth-jit.toml                    eth-jit-multi.toml
solana-arb.toml                 solana-copytrade.toml
solana-snipe.toml
```
Скопируйте подходящий, отредактируйте пулы/кошельки/риск-параметры под
себя. Запуск:
```bash
wakefinder run configs/eth-arb.toml
# или без pip install -e:
python -m wakefinder.cli run configs/eth-arb.toml
```
Профиль сам проверяет, что `chain`/`strategy` — валидная пара, до
попытки что-либо запустить.

### 1.5 Опционально, но рекомендуется

```
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```
Алерты про kill switch/просадку/зависшие позиции — без этого вы узнаете
о проблеме только зайдя в логи вручную.

```
DASHBOARD_USERNAME=...
DASHBOARD_PASSWORD=...
```
Обязательны ВМЕСТЕ, если планируете открыть веб-дашборд дальше
localhost — без них он отдаётся без аутентификации (с громким warning).

## Этап 2: DRY_RUN — прогон против живых данных без риска денег

```
DRY_RUN=true
```

Бот подключается к настоящему RPC, видит настоящий мемпул/пулы/цены,
считает настоящие решения — но НИ ОДНА транзакция не уходит в сеть.
Запускайте так минимум несколько дней на КАЖДУЮ стратегию, которую
планируете использовать, до перехода дальше.

**Как смотреть логи и дашборд, что означает "работает":**

- **Все стратегии**: heartbeat не протухает (см. RUNBOOK "Heartbeat
  stale"), kill switch не включается сам по себе, нет повторяющихся
  exception одного типа в логе.
- **arb**: `TwoPoolArbSimulator` находит возможности с ненулевой
  частотой (не "0 возможностей за 3 дня" — если так, скорее всего
  `reference_pools`/`min_amount_in` настроены неправильно, не то что
  "рынка нет"), симулированная прибыль не хронически отрицательная.
- **copytrade**: следит за `watched_wallets`, видит их сделки в логе
  (`_handle_swap`/consensus-проверка), при отсутствии активности китов —
  просто тишина, это нормально, не баг.
- **snipe**: видит новые пары через `PairCreatedWatcher`, фильтры
  (`check_new_pool`/`check_round_trip_sellable`) отсеивают большинство —
  это ожидаемо, снайпинг по конструкции пропускает почти всё.
- **liquidate**: скорее всего долго тишина (позиции с healthFactor < 1
  редки) — не повод для беспокойства за пару дней; если включён
  `LIQUIDATION_SCAN_ENABLED`, в логе должны появляться периодические
  сообщения о сканировании (раз в `LIQUIDATION_SCAN_INTERVAL_SECONDS`).
- **jit**: watcher должен видеть крупные свопы (`V3LargeSwapWatcher`,
  порог `JIT_MIN_SWAP_AMOUNT_IN_WEI`) в логе с какой-то частотой — если
  вообще ничего за несколько дней, порог, вероятно, завышен для этого
  пула.

Признак "что-то не так", а не просто рынок тихий: **одинаковое
исключение повторяется** (RPC timeout — провайдер плохой; decode error —
проблема с ABI/адресом; постоянный `getAmountsOut` revert — токен
неликвиден или адрес неверный).

## Этап 3: Форк-тест — проверка, что транзакции реально отправляются

DRY_RUN не отправляет транзакции — значит не проверяет саму механику
подписи/отправки/включения в блок. Для этого нужен форк mainnet
([Foundry](https://getfoundry.sh/), `anvil`):

```bash
anvil --fork-url $ETH_RPC_HTTP_URL
```

Поднимет локальный узел с реальным состоянием mainnet на текущий момент,
где можно тратить "поддельные" ETH без риска. Направьте
`ETH_RPC_WS_URL`/`ETH_RPC_HTTP_URL` на `http://127.0.0.1:8545`,
`DRY_RUN=false`, и прогоните каждую стратегию — теперь транзакции реально
строятся, подписываются и попадают в форк-блоки. Здесь всплывает то, что
DRY_RUN принципиально не может поймать: неверный `gas_limit`, ABI,
который не совпадает с реальным контрактом, revert по причине, которую
симуляция не воспроизвела.

В репозитории уже есть тесты именно такого рода —
`tests/test_fork_integration.py` (сам форкает публичный RPC через anvil,
если `anvil` не найден в PATH — тесты тихо пропускаются, не падают,
`pytest -rs` показывает причину skip'а явно).

## Этап 4: Пилот на малом реальном капитале

```
DRY_RUN=false
```

Начните с 1-2 самых зрелых стратегий (обычно `arb`/`snipe` — атомарные,
меньше движущихся частей, чем `copytrade`/`liquidate`/`jit`), $50-200 на
кошелёк, не весь капитал сразу.

Что смотреть на дашборде (`uvicorn wakefinder.web:app --reload`, или
`python -m wakefinder.launcher` для десктоп-версии):
- **Fill rate** (таблица "Метрики") — доля попыток, реально попавших в
  блок. Хронически низкий — тюньте `PROFIT_SHARE_BPS`/tip, а не
  игнорируйте.
- **Sharpe/Sortino и дрифт win-rate** по стратегии — качественный сигнал
  деградации раньше, чем это станет видно по просадке.
- **Портфель — реализованный PnL (USD)** — суммарная картина, не по
  одной сделке.

Встроенная защита на этом этапе — используйте её, не отключайте:
- **Kill switch**: `python -m wakefinder.common.killswitch status`
  (проверить), `stop`/`resume` (вручную остановить/снять). Срабатывает и
  автоматически при просадке (`MAX_DRAWDOWN_ETH`/`MAX_DRAWDOWN_SOL`) и при
  серии неудачных бандлов подряд (`MAX_CONSECUTIVE_FAILURES`, по
  умолчанию 5).
- **Canary — поэтапный ввод капитала**: `CANARY_START_FRACTION`
  (по умолчанию 1.0 = сразу полный размер) — выставьте меньше (например
  0.1) на первую неделю пилота, `CANARY_RAMP_TRADES` (по умолчанию 20) —
  через сколько успешных сделок размер дорастёт до полного. Работает у
  `arb`/`copytrade`/`snipe` на обеих сетях; `liquidate`/`jit` этот
  механизм не используют (там нет постепенного "размера позиции" в том
  же смысле).

Продержитесь минимум пару недель — рынок за 1 день не показывает
достаточно условий, чтобы делать выводы.

## Этап 5: Масштабирование и постоянная работа

Когда пилот отработал без сюрпризов:
- Увеличивайте капитал постепенно, не разом.
- Для постоянной работы без вашего компьютера — `deploy/systemd/*.service`
  (8 готовых юнитов, по одному на каждую chain+strategy комбинацию,
  `Restart=always`) или `Dockerfile`. Оба уже настроены на актуальный CLI
  (`wakefinder run configs/<профиль>.toml`) — отредактируйте сам профиль
  под боевые значения, не сам юнит.
- Добавляйте следующую стратегию только после того, как текущая
  стабильно отработала — не запускайте все 5 сразу с первого дня.

## Итоговый чеклист перед реальными деньгами

- [ ] `.env` заполнен, `ETH_PRIVATE_KEY`/`FLASHBOTS_SIGNER_KEY` — РАЗНЫЕ ключи, отдельные от любых других ваших кошельков
- [ ] Если используете `liquidate`/`jit` — `AAVE_POOL_DATA_PROVIDER_ADDRESS`/`AAVE_PRICE_ORACLE_ADDRESS` заменены на реальные (не дефолтные битые значения)
- [ ] DRY_RUN=true прогнан несколько дней без повторяющихся исключений
- [ ] Форк-тест (anvil) подтвердил, что транзакции реально строятся/подписываются/попадают в блок
- [ ] Пилот на $50-200 отработал минимум пару недель, дашборд/Sharpe не показывают деградацию
- [ ] Telegram-алерты настроены — узнаёте о проблеме не через ручной просмотр логов
- [ ] Знаете, как остановить всё разом (`killswitch stop`) прежде чем оно понадобится в панике
