# Wakefinder

Отдельный MEV searcher-бот (слежка за мемпулом → симуляция AMM → отправка бандла
через Flashbots/Jito) на Ethereum и Solana. Независим от BitbotBY — этот проект
on-chain, BitbotBY — CEX/ccxt.

Две независимые стратегии на каждой из двух сетей — 4 отдельных процесса:

| | Ethereum | Solana |
|---|---|---|
| **Арбитраж** | `wakefinder/chains/eth/main.py` | `wakefinder/chains/solana/main.py` |
| **Копитрейдинг** | `wakefinder/chains/eth/copytrade.py` | `wakefinder/chains/solana/copytrade.py` |

Что делать при срабатывании kill switch/drawdown/других защит — см. [RUNBOOK.md](RUNBOOK.md).

## Архитектура

```
                    ┌─────────────────────────────────────────┐
                    │        конфиг-профиль (TOML)             │
                    │  chain + strategy + пулы/кошельки/риск   │
                    └──────────────────┬────────────────────────┘
                                       │  wakefinder run <profile.toml>
                                       ▼
                    ┌─────────────────────────────────────────┐
                    │            wakefinder/cli.py              │
                    └──────────────────┬────────────────────────┘
              ┌────────────────────────┼────────────────────────┐
              ▼                        ▼                        ▼
     chains/eth/main.py      chains/eth/copytrade.py   chains/solana/{main,copytrade}.py
     (арбитраж)               (копитрейдинг)            (то же на Solana)
              │                        │                        │
              └────────────┬───────────┴────────────┬───────────┘
                           ▼                        ▼
                  ┌──────────────────────────────────────┐
                  │      wakefinder/common/ (общее)        │
                  │  killswitch · drawdown · consensus     │
                  │  adaptive_tip · allowlist · trade_log  │
                  │  wallet_stats · alerts · heartbeat     │
                  │  reconnect · keystore · price_feed     │
                  └──────────────────────────────────────┘
```

Каждый из 4 процессов — независимый watcher→simulator→sender конвейер
(`common/interfaces.py`: `MempoolWatcher`/`Simulator`/`BundleSender`, не
привязаны к конкретной сети). Общая инфраструктура (риск-контроль,
логирование, алерты) шарится через `common/`, но **у каждого процесса
должен быть свой кошелёк** — параллельная отправка транзакций с одного
кошелька из разных процессов ломает подсчёт nonce.

**Через что торгуем** (архитектурное решение, не настройка): на Ethereum —
Uniswap V2 и совместимые форки (Sushiswap) через прямой вызов роутера; на
Solana — [Jupiter](https://jup.ag) агрегатор, а не собственная кодировка
инструкций конкретного DEX (Raydium/Orca — слишком много PDA-выводов, чтобы
доверять без devnet-проверки). Это зашито в `chains/eth/abi.py`/`sender.py` и
`chains/solana/*.py` — не параметр конфига.

**Многосетевой охват**: добавить ещё одну EVM-сеть (BSC/Arbitrum/Base/...) —
дёшево: копируете `chains/eth/` почти 1:1, меняются адреса роутера/фабрики/WETH
и RPC URL — большинство таких сетей используют форки того же Uniswap V2 ABI.
Не-EVM сеть, отличная от Solana — полноценный новый chain-модуль с нуля, как
Solana в своё время. Ни то, ни другое не реализовано сейчас — только архитектурно готово.

## Быстрый старт: от нуля до первого запуска

### 1. Установка

```bash
git clone <этот репозиторий>
cd Wakefinder
pip install -e ".[dev]"
```

### 2. Заведите отдельный кошелёк

**Никогда не используйте основной кошелёк.** Заведите новый, ТОЛЬКО для бота:
- Ethereum: любой стандартный способ (MetaMask → "Create Account", `eth_account.Account.create()` в Python, `cast wallet new` из Foundry) — нужен приватный ключ в hex (`0x...`).
- Solana: `solana-keygen new` (Solana CLI) или Phantom/Solflare → "Create New Wallet" → экспорт приватного ключа (base58).
- Держите на нём **минимальный баланс**, регулярно выводите прибыль на холодный кошелёк.
- Для Ethereum-арбитража нужен ЕЩЁ ОДИН отдельный ключ — `FLASHBOTS_SIGNER_KEY`, только для репутации у relay, никогда не финансируется.
- Секрет храните либо plaintext в `.env` (проще, начните с этого), либо через шифрованное хранилище — см. раздел "Безопасность" ниже.

### 3. Получите доступ к RPC

- **Ethereum**: нужны ОБА — WS-эндпоинт (подписка на мемпул) и HTTP-эндпоинт, который поддерживает `eth_getRawTransactionByHash` (не все провайдеры это дают — проверьте в документации провайдера, бот падает громко, если его нет). Варианты: [Alchemy](https://alchemy.com), [Infura](https://infura.io), [QuickNode](https://quicknode.com) — у всех есть бесплатный тир, для реальной торговли из-за скорости/лимитов обычно берут платный.
- **Solana**: тоже WS + HTTP. Варианты: [Helius](https://helius.dev), [QuickNode](https://quicknode.com), [Triton](https://triton.one). Публичный `api.mainnet-beta.solana.com` для продакшена не годится (жёсткие rate-лимиты).
- **Тестнет обязателен перед реальными деньгами**: Ethereum Sepolia (RPC — те же провайдеры, отдельный эндпоинт; ETH — из faucet, например `sepoliafaucet.com`), Solana devnet (`solana airdrop` через CLI или `solfaucet.com`).

### 4. Найдите, за чем следить

- **Пулы для арбитража**: нужен адрес целевого пула И адрес референсного пула ТОЙ ЖЕ пары на ДРУГОМ DEX (без второго источника ликвидности арбитража нет). Ethereum — [Etherscan](https://etherscan.io) (вкладка контракта пары) или [Dexscreener](https://dexscreener.com); Solana — [Solscan](https://solscan.io), [Dexscreener](https://dexscreener.com), сайты Raydium/Orca.
- **Кошельки для копитрейдинга**: сам блокчейн не размечает адреса по "умности" — источники:
  - Ручная/внешняя аналитика: [Nansen](https://nansen.ai), [Arkham](https://arkham.com), [DeBank](https://debank.com), Etherscan "Top Accounts".
  - Наш `wakefinder/wallet_scanner.py` — первый дешёвый фильтр: `find_candidate_wallets_eth`/`find_candidate_wallets_solana` находят, кто вообще торговал в интересующих пулах и как часто (тот же RPC, без нового источника данных), опционально `filter_by_etherscan_activity` отсекает свежие/одноразовые адреса. Это список кандидатов, не готовый вердикт — финальную курацию всё равно делаете вы или внешняя аналитика.

### 5. Настройте секреты и профиль

```bash
cp .env.example .env   # впишите RPC/ключи — .env никогда не коммитить
```

Затем скопируйте и отредактируйте подходящий профиль из `configs/` (адреса
внутри — заглушки, замените на найденные на шаге 4):

```bash
cp configs/eth-copytrade-conservative.toml configs/my-profile.toml
# отредактируйте watched_wallets, token_denylist, риск-параметры
```

Про формат профилей и как переключаться между стратегиями/скоростными режимами — раздел "Конфиг-профили и CLI" ниже.

### 6. Проверьте на тестнете

Смените `.env` на тестнетовые RPC/ключи (Sepolia/devnet), запустите с
минимальным капиталом, убедитесь, что весь цикл (обнаружение → симуляция →
отправка → лог) реально работает, прежде чем касаться mainnet-капитала. Это
единственный шаг, который бот не может проверить сам за вас.

### 7. Запустите

```bash
wakefinder run configs/my-profile.toml
```

(или `python -m wakefinder.cli run configs/my-profile.toml`, если без `pip install -e .`)

### 8. Мониторьте

```bash
python -m wakefinder.dashboard              # открытые позиции + статистика по кошелькам
python -m wakefinder.common.killswitch status
```

Настройте `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` в `.env` для алертов. При
срабатывании kill switch/просадки/других защит — [RUNBOOK.md](RUNBOOK.md).

## Конфиг-профили и CLI

`wakefinder/cli.py` — единая точка входа поверх TOML-профилей вместо
захардкоженных launcher-скриптов на каждую комбинацию сеть+стратегия.

```bash
wakefinder run configs/eth-arb.toml
wakefinder run configs/eth-copytrade-fast-memecoin.toml
```

Профиль (см. примеры в `configs/`) задаёт:
- `chain` (`"eth"`/`"solana"`) и `strategy` (`"arb"`/`"copytrade"`) — какой из 4 `run()` вызвать;
- `[[pools]]`/`[[reference_pools]]`/`[[solana_pools]]` — пулы (формат под каждую сеть, см. примеры);
- `watched_wallets`, `token_allowlist`, `token_denylist` — списки адресов;
- `[risk]` — переопределение риск-параметров `Settings` (полный список ключей — `_RISK_ENV_MAP` в `cli.py`), применяется через переменные окружения ДО первого чтения конфига в процессе.

**Один процесс = один профиль** — то же допущение, что и раньше про раздельные кошельки/процессы на стратегию.

### Мемкоин-профиль: конкурируем с китами, не опаздываем

`configs/eth-copytrade-fast-memecoin.toml` — **не новая стратегия и не новый
код**, тот же `chains/eth/copytrade.py`, что и в консервативном профиле,
только другие числа риска. Единственный по-настоящему крупный рычаг скорости,
целиком в наших руках — окно консенсуса:

| Параметр | Консервативный | Быстрый (мемкоин) | Почему |
|---|---|---|---|
| `copytrade_min_consensus_wallets` | 3 | 1 | ждать второго кита = отдать движение цены тем, кто не ждал |
| `copytrade_consensus_window_seconds` | 180 | 5 | при `wallets=1` не влияет, но безопасный дефолт |
| `copytrade_size_pct` | 2% | 0.5% | меньше на сделку — плата за повышенный риск скорости |
| `copytrade_stop_loss_check_interval_seconds` | 60 | 5 | мемкоины волатильнее — раз в минуту слишком редко |
| `min_reference_liquidity_eth` | 1.0 | 0.1 | у свежих мемкоинов пулы обычно мельче дефолтного порога |

Остальные стадии пайплайна (обнаружение pending-tx, отправка в публичный
мемпул) уже настолько быстрые, насколько это возможно без колокации/приватного
ордерфлоу — это осознанно вне охвата проекта (см. "Безопасность").

**Чек-лист перед реальным запуском мемкоин-профиля** (операционная
ответственность, не технический баг):
- [ ] `token_denylist` вручную укомплектован известными fee-on-transfer/rebasing токенами, которые собираетесь торговать через whitelisted пары — у мемкоинов это встречается намного чаще, чем у голубых фишек.
- [ ] Понимаете, что снижение `MIN_REFERENCE_LIQUIDITY_ETH`/`_SOL` — это прямое снижение защиты от манипуляции ценой (раздел "Инфраструктурная надёжность"), не бесплатная опция.
- [ ] `copytrade_max_total_exposure_pct` выставлен с учётом того, что позиции в мемкоинах могут обнулиться (rug pull) — стоп-лосс не защищает от полной потери ликвидности пула.
- [ ] Арбитраж-профиль на мемкоины НЕ настраивается — у свежего токена обычно нет второго ликвидного пула на другом DEX, а без него арбитража по конструкции нет.

## Портфельный риск-контроль (все 4 процесса: ETH/Solana × арбитраж/копитрейдинг)

- **Единый kill switch** (`wakefinder/common/killswitch.py`) — все 4 процесса
  проверяют ОДИН файл (по умолчанию абсолютный путь в домашней директории,
  не зависит от рабочей директории процесса). Управление:
  ```bash
  python -m wakefinder.common.killswitch stop     # остановить всё
  python -m wakefinder.common.killswitch resume    # снять
  python -m wakefinder.common.killswitch status
  ```
- **Circuit breaker по просадке** (`wakefinder/common/drawdown.py`) —
  независимо от `MAX_CONSECUTIVE_FAILURES` (тот ловит только "бандл не
  попадает в блок"), считает суммарную РЕАЛИЗОВАННУЮ прибыль/убыток по всем
  стратегиям одной сети за скользящее окно (`DRAWDOWN_WINDOW_SECONDS`, по
  умолчанию 24ч), плюс НЕРЕАЛИЗОВАННУЮ переоценку всех открытых
  копитрейд-позиций на момент проверки (копитрейд-энтрипоинты сами
  переоценивают позиции живым RPC/quote-запросом и передают число в
  `check_drawdown(unrealized_pnl=...)`) — и сам включает kill switch при
  превышении `MAX_DRAWDOWN_ETH` / `MAX_DRAWDOWN_SOL`.
- Оба реализуют Tier 0 из архитектурного аудита; третий пункт Tier 0 —
  реальная валидация на testnet/devnet — не может быть сделана автоматически,
  нужны профинансированные тестовые кошельки и живой RPC-провайдер (см.
  "Быстрый старт" шаг 6).

## Инфраструктурная надёжность (Tier 1–2)

- **Защита референсного пула от манипуляции** (`MIN_REFERENCE_LIQUIDITY_ETH` /
  `_SOL`, по умолчанию 1 ETH / 10 SOL) — тонкий референсный пул дёшево
  сдвинуть в том же блоке/слоте, что и атакуемый, подсунув боту фиктивно
  прибыльную котировку; симулятор на обеих сетях отказывается доверять
  пулам ниже порога.
- **Автопереподключение WS** (`wakefinder/common/reconnect.py`) — все 4
  watcher'а обёрнуты в `with_reconnect`, который перехватывает обрыв
  соединения (провайдер рестартует ноду, сетевой блип) и переподключается с
  экспоненциальным backoff вместо падения всего процесса.
- **Heartbeat** (`wakefinder/common/heartbeat.py`) — каждый процесс пишет
  timestamp в свой файл в `HEARTBEAT_DIR` каждые `HEARTBEAT_INTERVAL_SECONDS`
  (по умолчанию 30с). Ловит тихое зависание event loop, которое не даёт
  исключения (поэтому его не ловят ни kill switch, ни `with_reconnect`).
  Проверка снаружи:
  ```bash
  python -m wakefinder.common.heartbeat eth_arb.heartbeat 90
  ```
- **Process supervision** (`deploy/systemd/*.service`) — шаблоны systemd-юнитов
  с `Restart=always` на все 4 процесса. Намеренно не реализовано на Python —
  супервизия процесса это работа ОС/init-системы, а не самого бота; см.
  комментарии внутри юнитов про замену `ExecStart` на `wakefinder run <профиль>`
  (голый `python -m wakefinder.chains.*` запускается с пустыми
  `pool_registry`/`watched_wallets` — это smoke-test заглушка).

## Бэктестинг (Tier 4, ETH)

`wakefinder/backtest.py` — `run_backtest(w3, target_router, reference_pools,
from_block, to_block)`. Не новый источник данных: тот же `ETH_RPC_HTTP_URL`,
что и live-режим — сканирует исторические `Swap`-логи целевых пулов через
`eth_getLogs`, реконструирует `PendingSwap` по каждому и прогоняет через
ЖИВОЙ `TwoPoolArbSimulator.simulate()` (тот же код, что реально торгует, не
копия логики) на резервах ДО этого исторического свопа.

Честные ограничения:
- Публичные RPC ограничивают диапазон/глубину `eth_getLogs` — `chunk_size`
  разбивает диапазон, но для старой истории может понадобиться архивный узел.
- НЕ учитывает конкуренцию с другими searcher-ботами за тот же блок —
  верхняя граница достижимой прибыли, не гарантированный исторический результат.
- Использует ТЕКУЩИЕ `MAX_GAS_GWEI`/`MIN_REFERENCE_LIQUIDITY_ETH`/т.п., не
  исторические условия сети на момент каждого блока.

Solana сознательно не реализован тем же способом — там нет прямого аналога
`eth_getLogs`; пришлось бы восстанавливать историю через
`getSignaturesForAddress` + разбор транзакций, что на публичных RPC менее
надёжно (обрезка истории, пагинация) — честное ограничение, не недосмотр.

## Операционные требования (путь Ethereum)

- **RPC-провайдер обязан поддерживать `eth_getRawTransactionByHash`.** Не
  универсально — если ваш не поддерживает, бот падает громко (логирует и
  пропускает возможность). Проверьте это заранее.
- **Дайте approve каждому роутеру, через который может пройти сделка** —
  целевому роутеру (`ETH_ROUTER_ADDRESS`) *и* каждому референсному роутеру,
  переданному в `reference_pools` — от кошелька `ETH_PRIVATE_KEY`, на каждый
  задействованный токен. Разовая настройка, не часть горячего пути.
- `reference_pools` должен сопоставлять каждый отслеживаемый пул с пулом той
  же пары на действительно другом DEX — бэкран против одного-единственного
  пула не является арбитражем.
- Своп попадает в обработку по ИЛИ: размер (`min_amount_in`) ИЛИ отправитель
  в `watched_wallets`. Список кошельков берётся извне — см. "Быстрый старт" шаг 4.

## Безопасность

- Начинайте с тестнета (Sepolia) — никакого реального капитала, пока полный
  цикл там не проверен (см. "Быстрый старт" шаг 6).
- `MAX_GAS_GWEI` / `MAX_CAPITAL_PER_BUNDLE_ETH` в `.env` ограничивают риск на
  бандл; `ETH_ROUTER_ADDRESS` сверяется с allowlist в `config.py` —
  неизвестный роутер (опечатка или подменённый `.env`) не даёт боту запуститься.
- Бот отказывается стартовать, если `ETH_PRIVATE_KEY` и `FLASHBOTS_SIGNER_KEY`
  указывают на один и тот же кошелёк — на ключе подписи никогда не должно быть средств.
- **Шифрованное хранилище ключей** (`wakefinder/common/keystore.py`) —
  альтернатива голому ключу в `.env`. Зашифровать:
  `python -m wakefinder.common.keystore <путь>` (пассфраза и ключ вводятся
  интерактивно через `getpass`, не попадают в аргументы/историю shell). Затем
  вместо `ETH_PRIVATE_KEY` укажите `ETH_PRIVATE_KEY_FILE=<путь>` и
  `WALLET_KEY_PASSPHRASE` в окружении процесса (аналогично для
  `FLASHBOTS_SIGNER_KEY_FILE`/`SOLANA_PRIVATE_KEY_FILE`) — ровно один
  источник на ключ, plaintext ИЛИ файл, бот откажется стартовать, если задано
  и то, и другое, или ни то, ни другое. Не заменяет HSM/KMS (см. docstring
  модуля) — пассфраза всё равно должна быть в окружении живого процесса.
- Стратегия по умолчанию — backrun/арбитраж, не sandwich (sandwich напрямую
  вредит отслеживаемому трейдеру — это осознанный опт-ин, не поведение по умолчанию).
- **Kill switch**: единый на все 4 процесса, см. раздел "Портфельный риск-контроль" выше — `python -m wakefinder.common.killswitch stop|resume|status`.
- **Все секреты — `SecretStr`**: RPC URL, приватные ключи, пассфраза keystore,
  Telegram-токен — pydantic скрывает значение в `repr()`/`str()`, чтобы
  необработанный traceback/лог не слил его в открытом виде. Регрессия
  проверяется тестом (`tests/test_security.py`).
- **Предупреждение о правах доступа**: при старте `get_settings()` проверяет
  режим `.env` и всех заданных `*_KEY_FILE` — если файл читаем/писуем группой
  или всеми (не `600`), в лог идёт заметное предупреждение (не блокирует
  старт — например, в контейнере под конкретным пользователем это не всегда
  применимо). Частая причина утечки на общих серверах.
- **Сканирование зависимостей** (`pip-audit` в `.github/workflows/ci.yml`) —
  на каждый push/PR проверяет известные CVE в разрешённом дереве зависимостей.
- Баланс проверяется перед каждым бандлом — и нативный ETH (покрывает газ на
  обе ноги по комиссии, которую бот собирается предложить), и `token_in` — бот
  пропускает возможность, а не подписывает транзакцию, на которую не хватает средств.
- Tip за включение бандла масштабируется от `PROFIT_SHARE_BPS` (по умолчанию
  90%) захваченной прибыли самой возможности, а не фиксированная ставка —
  предложение цены близко к реальной выгоде возможности — именно это нужно,
  чтобы выиграть аукцион block builder'а за включение против других searcher-ботов.
- **Колокация/приватный ордерфлоу — осознанно вне охвата.** Мы не пытаемся
  конкурировать с профессиональными MEV-шопами на физической задержке
  (colocated-серверы у валидаторов, приватные сделки с билдерами) — вся
  скорость, которую можно выжать, выжимается на уровне конфига/архитектуры
  (см. "Мемкоин-профиль" выше), не на уровне инфраструктуры.

## Операционные требования (путь Solana)

- **У Solana нет публичного pending-мемпула** для сторонних searcher'ов —
  приватный shred-stream Jito требует отдельного одобрения. Watcher наблюдает
  не "ожидающую" транзакцию, а изменение резервов пула сразу после того, как
  своп уже подтверждён — гонка идёт за следующий слот, не за тот же блок.
- **Watchlist по конкретным кошелькам для арбитражного пути** (`main.py`) не
  реализован — `accountSubscribe` на vault-аккаунт не даёт отправителя. Для
  копитрейдинга (`copytrade.py`) watchlist есть — через отдельный
  `wallet_watcher.py` (см. секцию "Копитрейдинг" ниже).
- Ноги свопа строит Jupiter (`jupiter_python_sdk`), а не собственная кодировка
  инструкций Raydium — там ~18 аккаунтов и PDA-деривации, которые нельзя
  проверить без devnet. Таргетинг на пул — на уровне DEX через `exclude_dexes`,
  не гарантированно на уровне конкретного `pool_id`.
- `reference_pools`/`pools` должны указывать реальные адреса base/quote
  vault-аккаунтов и label DEX, который понимает Jupiter (`"Raydium"`,
  `"Orca"` и т.п.).
- Требует, чтобы у кошелька `SOLANA_PRIVATE_KEY` уже были ассоциированные
  token-аккаунты (ATA) под задействованные токены — Jupiter их не создаёт на лету.
- Bundle без tip-транзакции Jito block engine не рассматривает вообще — это
  встроенный обязательный аналог builder-payment, не опциональная настройка.
  Tip-аккаунт запрашивается динамически через `getTipAccounts`, не хардкодится.

## Quant-hardening (обе сети)

- **Token allowlist**: `token_allowlist` — не автодетектор honeypot'ов
  (ненадёжен без анализа байткода), а явная, проверяемая граница того, что и
  так подразумевалось: бот торгует только заранее сконфигурированными
  токенами. Пустой allowlist = проверка выключена (для дева/тестов); в
  проде указывайте явно.
- **Token denylist**: `token_denylist` — курируемый вручную список известных
  fee-on-transfer/rebasing токенов (та же причина, что и с allowlist —
  автоматический анализ байткода ненадёжен, поэтому списка по умолчанию
  нет). Такие токены ломают допущение `apply_swap()`/`get_amount_out()` о
  сохранении суммы при переводе. На арбитражных путях проверяется при
  старте (пулы известны заранее); на копитрейдинге — по каждому свопу в
  рантайме (токены заранее не известны).
- **Адаптивный tip**: `PROFIT_SHARE_BPS` — это стартовое значение, дальше им
  управляет `AdaptiveTipController` (AIMD) — не попал бандл в блок, ставка
  растёт; попал — немного снижается, оставляя больше маржи. Не ML/bandit,
  просто тот же принцип, что управление перегрузкой в TCP.
- **Конвертация газа/кэпа для не-WETH token_in** (ETH): газ и
  `MAX_CAPITAL_PER_BUNDLE_ETH` считаются в реальных ETH wei, но арбитражная
  математика сравнивает их с прибылью в единицах `token_in`. `TwoPoolArbSimulator`
  конвертирует через `getAmountsOut(WETH → token_in)` на целевом роутере,
  если `token_in` не сам WETH (`ETH_WETH_ADDRESS`); нет прямой пары — сделка
  пропускается с явной причиной, не тихим нулём. На Solana — тот же принцип:
  конвертация через Jupiter-квоту `wSOL → token_in` (`SOLANA_WSOL_ADDRESS`),
  быстрый путь без запроса сохранён для `token_in == wSOL`.
- **Автостоп по сериям неудач**: `MAX_CONSECUTIVE_FAILURES` (по умолчанию 5) —
  после стольких подряд непопавших в блок бандлов бот сам ставит kill switch.
  Не защита от прямой потери денег (неотправленный/непопавший бандл ничего не
  стоит), а сигнал "что-то системно не так", который нельзя оставлять
  человеку заметить самому.
- **Лог сделок**: `TRADE_LOG_FILE` (по умолчанию `trades.jsonl`) — append-only
  JSONL с каждой попыткой (симулированная прибыль, попал ли в блок, tx-ссылки).
  Не полноценный PnL-дашборд — тот потребовал бы снимков баланса до/после
  каждой сделки, это отдельная задача; здесь только сырые данные для анализа.
- **Приоритизация возможностей в арбитраже — сознательно не реализована.**
  MEV-возможности живут доли секунды; буферизация нескольких для сравнения
  сделала бы котировки устаревшими к моменту выбора. (Для копитрейдинга,
  где позиция держится минутами/часами, буферизация УМЕСТНА — см. консенсус ниже.)

## Копитрейдинг (`wakefinder/chains/{eth,solana}/copytrade.py`)

Принципиально другая стратегия, чем backrun-арбитраж (`main.py`/`simulator.py`):
не арбитражим ценовой перекос от сделки кита, а **зеркалим её направление** —
покупаем то же, что купил watched-кошелёк, держим позицию, продаём позже.
**Другой профиль риска**: арбитраж никогда не держит инвентарь дольше одного
атомарного бандла (гарантированная на момент исполнения прибыль или ничего);
копитрейдинг реально держит открытую направленную позицию между входом и
выходом — это не гарантированно прибыльная сделка, это ставка.

- **Размер позиции — доля НАШЕГО баланса** (`COPYTRADE_SIZE_PCT`, по
  умолчанию 2%), не сумма кита. У кита может быть бюджет в миллионы, у нас —
  сколько есть; бот копирует направление ставки, не её абсолютный размер.
  Пересчитывается заново перед каждым входом по текущему балансу.
- **Вход требует консенсуса**: `COPYTRADE_MIN_CONSENSUS_WALLETS` (по
  умолчанию 2) разных watched-кошельков должны купить один и тот же токен в
  течение `COPYTRADE_CONSENSUS_WINDOW_SECONDS` (по умолчанию 120с) — один кит
  может ошибаться, несколько независимых, сходящихся почти одновременно —
  сильнее сигнал. Логика — `wakefinder/common/consensus.py`. Это САМЫЙ
  большой рычаг скорости в пайплайне — см. "Мемкоин-профиль" выше про то,
  как его тюнить под скорость.
- **Выход по двум независимым триггерам**: зеркальный (watched-кошелёк
  продаёт токен, который мы держим) ИЛИ стоп-лосс (`COPYTRADE_STOP_LOSS_PCT`,
  по умолчанию 20%, проверка каждые `COPYTRADE_STOP_LOSS_CHECK_INTERVAL_SECONDS`
  = 60с фоновой задачей) — защита на случай, если все киты держат "до нуля"
  или мы упустили их выход.
- **Позиции — плоский JSON-файл** (`COPYTRADE_POSITIONS_FILE` /
  `SOLANA_COPYTRADE_POSITIONS_FILE`), переживает рестарт — краш с открытой
  позицией не значит молча забытый риск.
- **ETH**: следует за китом в ЛЮБОЙ токен, не только предсконфигурированный —
  адрес пула при промахе по `pool_registry` выводится через `getPair()`
  фабрики Uniswap V2 (`ETH_FACTORY_ADDRESS`), включается только для
  watchlist-триггеров, не меняет поведение арбитражного пути.
- **Solana**: свой watcher (`wallet_watcher.py`) — DEX-агностичный, читает
  `preTokenBalances`/`postTokenBalances` подписчика из транзакции (через
  `logsSubscribe(mentions=[wallet])` на `commitment=Processed` — самый быстрый
  публичный уровень; сама транзакция выбирается на `commitment=Confirmed` с
  короткими повторами, `processed` для `getTransaction` в основном не
  поддерживается публичными RPC), а не декодирует инструкции конкретного DEX.
  Работает одинаково для Raydium/Orca/Jupiter/чего угодно ещё, которым мог
  торговать отслеживаемый кошелёк.
- **ETH-скорость входа**: собственные сделки копитрейдинга (вход и выход) идут
  в ПУБЛИЧНЫЙ мемпул (`send_raw_transaction`), не через Flashbots — сознательный
  выбор в пользу скорости, в обмен на риск быть засэндвиченным другими
  MEV-ботами — та же атака, которую применяет арбитражная часть этого
  проекта против чужих сделок.
- **Кэп суммарной экспозиции**: `COPYTRADE_MAX_TOTAL_EXPOSURE_PCT` (по
  умолчанию 20%) — ограничивает не одну сделку, а сумму entry_amount_in по
  ВСЕМ открытым позициям сразу; без этого несколько последовательных входов
  по `COPYTRADE_SIZE_PCT` каждый могли бы незаметно съесть большую часть баланса.
- **Требует ОТДЕЛЬНОГО процесса** от `main.py` (арбитраж) — если использовать
  тот же кошелёк одновременно с обеими стратегиями, они независимо считают
  nonce/отправляют транзакции и будут конфликтовать. Разделяйте кошельки или
  не запускайте одновременно.

## Наблюдаемость

- **Трекинг результативности кошельков** (`wakefinder/common/wallet_stats.py`):
  агрегирует `trade_log.jsonl` по полю `wallet` (записи `copytrade_entry`/
  `copytrade_exit`) — приблизительный net PnL и win rate на кошелёк, чтобы видеть,
  какие watched-кошельки из вашего списка реально прибыльны. Оценка на
  котируемых, не аудированных постфактум суммах (см. docstring модуля).
- **CLI-дашборд**: `python -m wakefinder.dashboard` — печатает открытые позиции
  (ETH/Solana) и статистику по кошелькам в терминал. Переиспользует
  `wallet_stats.py`, никакого веб-сервера.
- **USD-оценка** (`wakefinder/common/price_feed.py`): дашборд подтягивает
  курс ETH/SOL с публичного CoinGecko endpoint (без API-ключа) и показывает
  `net_pnl~` ещё и в `$` рядом с нативными единицами — `--no-usd`, чтобы
  пропустить сетевой запрос (офлайн/приватность). Только для отображения:
  торговая логика (drawdown, кэпы) остаётся в нативных единицах — см.
  docstring `drawdown.py`, почему конвертация туда сознательно не добавлена.
- **Telegram-алерты** (`wakefinder/common/alerts.py`): `TELEGRAM_BOT_TOKEN` /
  `TELEGRAM_CHAT_ID` — уведомления на kill switch (ручной и авто по сериям
  неудач) и стоп-лосс копитрейдинга. Пустые значения = алерты выключены.
- **Сканер кандидатов в watchlist** (`wakefinder/wallet_scanner.py`) — НЕ
  рейтинг прибыльности (для этого нужна была бы полная реконструкция истории
  каждого кандидата, по сложности не уступающая бэктестингу под каждого
  отдельно), а дешёвый первый фильтр — см. "Быстрый старт" шаг 4.
